# v4.27.0 설계 기록

v4.27.0에서 넣은 것과 넣지 않은 것을 가른 기록이다.
넣지 않은 항목도 이유와 함께 남긴다. 같은 항목을 다음에 다시 검토할 때 이 문서에서 시작한다.

v4.27.1에서 구현 스킬과 리뷰 템플릿의 해당 문구를 처음 보는 사람도 읽을 수 있는 문장으로 다시 썼다.
규칙의 뜻은 바꾸지 않았고 용어는 처음 나올 때 풀어 썼다.

## 판단 기준

세 질문에 모두 "예"인 것만 넣었다. v4.26.0 때와 같은 기준이다.

1. ACL이 실제로 겪는 실패 모드를 막는가.
2. ACL의 기존 계약과 충돌하지 않는가. 계약은 SPEC 선행, 동결 인수 테스트, fail-closed 게이트, 리뷰 형식 게이트다.
3. 비용보다 효과가 큰가. 세션마다 주입되는 규칙은 매번 토큰이 든다.

효과를 재지 않은 규칙 문장은 쌓일수록 비용만 는다.
그래서 문장 추가는 적게 하고, 구조로 넣을 수 있는 것은 구조로 넣었다.

### 왜 넣었나

**A. 서브에이전트 착수 규칙 주입.**
v4.26.0에서 서브에이전트 착수 지시 3항목을 `shared-rules.md`에 넣었다.
그러나 그 규칙은 오케스트레이터가 프롬프트에 옮겨 적어야만 서브에이전트에 닿는다.
옮겨 적지 않으면 서브에이전트는 자기 게이트를 덧붙이거나 사용자에게 묻는다.
공식 문서는 SubagentStart가 서브에이전트 컨텍스트에 텍스트를 더할 수 있다고 한다. SessionStart 주입이 서브에이전트에 닿는지는 문서에 없다.

훅의 범위는 세 가지로 정했다.

| 결정 | 이유 |
|------|------|
| ACL 실행 중인 프로젝트에서만 주입 | ACL이 아닌 작업의 서브에이전트까지 바꾸지 않는다. 판정은 read-guard와 같은 두 파일 신호다 |
| 착수 규칙 3항목만 넣고 보고 작성 규칙은 넣지 않음 | 리뷰 서브에이전트의 finding 형식과 충돌한다. 지시문의 출력 형식이 우선한다고 본문에 적었다 |
| stdin을 읽지 않음 | 판단에 필요한 것은 작업 디렉토리 파일뿐이다. stdin 대기가 서브에이전트 생성을 멈추게 할 수 있다. 테스트가 이를 실행으로 검사한다 |

본문의 단일 출처는 `rules/subagent-briefing.md`다. `shared-rules.md`의 세 항목과 제목이 같은지 bats가 검사한다.
두 곳뿐인 사본이라 별도 검사 스크립트를 두지 않고 테스트 1개로 맞춘다.
훅 출력이 서브에이전트 모델 컨텍스트에 보이는 것은 카나리아 실행으로 확인했다. 방법과 결과는 아래 근거 숫자 절에 있다.
그래서 ACL 활성 프로젝트에서는 세 항목을 지시문에 다시 옮겨 적지 않아도 된다.
완료 기준과 출력 형식은 계속 지시문에 쓴다. 훅이 돌지 않는 경우의 목록은 `shared-rules.md`에 있다.

**B. diff 밖 호출부 읽기.**
리뷰어에게 diff만 주면 시그니처나 반환값을 바꾼 변경이 미변경 호출부를 깨뜨려도 보이지 않는다.
라운드 2+ 래칫은 미변경 코드 지적에 정당화를 요구한다. 그대로 두면 이번 diff가 깨뜨린 호출부도 LOW로 눌린다.
그래서 래칫 규칙 1과 2에 예외를 적었다. 이번 diff가 깨뜨린 호출부는 delta의 영향으로 보고 원 severity로 보고한다.
이전 라운드에도 있던 결함은 이 예외에 들지 않는다.

**C. 규모 결함과 부하 기준.**
기존 PERF 관점은 N+1, 페이지네이션, 메모리 누수 세 줄이었다.
인스턴스가 둘 이상인데 인메모리 상태를 쓰는 결함, 프로세스마다 같은 일을 반복하는 결함, 상한 없이 커지는 컬렉션을 더했다.
동시성 결함은 DATA와 SEC 관점에 이미 있어 넣지 않았다.
부하 기준이 없으면 PERF 지적은 "트래픽이 많으면"이라는 가정에 기대 severity가 흔들린다. SPEC 비기능 요구를 기준으로 삼고, 없으면 가정을 적게 했다.

**D. NOT_CHECKED 줄.**
기존 형식에서 리뷰어는 "결함 0건"과 "확인 못 함"을 구분해 낼 방법이 없었다.
둘 다 NO_FINDINGS가 되면 읽지 못한 범위가 깨끗한 범위로 집계된다.
`NOT_CHECKED` 줄은 finding이 아니라 남은 것으로 옮긴다. 변경 파일을 읽지 못했다는 내용이면 그 라운드는 0건 라운드로 치지 않는다.
최종 보고의 확인 못 한 것은 이미 보고 작성 규칙의 "남은 것"이 맡는다. 그래서 이 줄은 리뷰어 출력에만 둔다.
선택 줄이라 없어도 형식이 깨지지 않는다. 팀 모드 완료 게이트에 넣어 실행해 보았고 결과는 근거 숫자 절에 있다.

**E. shortcut 표시.**
의도적 단순화와 실수는 코드만 봐서는 구분되지 않는다.
리뷰어는 단순화를 결함으로 지적하고, 구현자는 다시 설명하고, 라운드가 하나 소모된다.
한계와 업그레이드 조건을 주석으로 남기면 리뷰가 그 한계 안에서는 결정으로 다룬다.
SPEC 규모가 그 한계를 넘거나 한계를 넘을 때 데이터가 조용히 사라지면 finding이다.
되돌리기 비싼 한계는 결정 로그에도 남긴다.

**F. 구현 사다리와 줄이지 않는 것.**
Step 2-1.5는 재사용 탐색만 다뤘다. 재사용할 것이 없을 때의 순서가 없었다.
사다리는 기존 코드, 표준 라이브러리, 설치된 의존성, 새 코드 순이다.
첫 칸 "만들지 않는다"는 SPEC 밖의 것에만 적용한다. SPEC에 있는 것을 이 칸으로 빼면 동결 인수 테스트가 깨진다.
막연한 요청을 가장 작은 버전으로 줄여 해석하지 않는다. ACL은 막연한 요청을 Phase 0 명확성 인터뷰로 보낸다.
"줄이지 않는 것" 목록은 사다리가 입력 검증과 에러 처리를 빼는 근거가 되지 않게 막는다.

**G. 원인에서 한 번 고치기.**
리뷰 수정이 호출부마다 우회 코드를 덧대면 같은 원인의 지적이 다음 라운드에 다른 호출부에서 다시 나온다.
v4.26.0의 근본 원인 병합은 지적을 합치는 규칙이었다. 이번에는 고치는 쪽에도 같은 규칙을 두었다.
코드를 옮기거나 합칠 때 검증과 에러 처리가 빠지는 것도 같은 묶음으로 막는다.

## 넣지 않은 것

| 검토한 것 | 넣지 않은 이유 |
|-----------|----------------|
| 사다리 끝에 "가장 짧은 코드로" 칸 | 짧게 쓰라는 지시는 입력 검증과 에러 처리를 먼저 깎는다. 잘못된 행에서 터지는 5줄 코드가 그 예다 |
| 규모나 코드 줄이기를 위한 리뷰 카테고리 신설 | 팀 모드 완료 게이트가 finding 제목 접두어를 6개로 고정해 센다. 새 접두어는 게이트를 깨뜨린다. 관점 분할 표도 다시 짜야 한다 |
| "더 줄일 수 있다"를 리뷰 finding으로 | ACL은 라운드 1~2의 MEDIUM을 즉시 수정한다. 이 지적이 MEDIUM이 되면 의무 수정 라운드가 생겨 v4.15.0에서 막은 발산이 돌아온다. 줄이기는 구현 사다리에서 다룬다 |
| finding에 "넘어가면 생기는 일" 칸 | 심각도 기준이 이미 영향을 정의한다. 같은 내용을 두 칸에 쓰게 된다 |
| 줄 수나 토큰 절감 집계 | 줄 수는 ACL의 완료 기준이 아니다. ACL은 게이트 통과로 완료를 판정한다 |
| 실행 엄격도 단계 | ACL의 엄격도는 DoD와 게이트가 정한다. 단계를 하나 더 두면 같은 실행이 단계에 따라 다른 계약을 갖는다 |
| 프롬프트 비교 벤치마크 하네스 | ACL에는 LLM 평가 하네스가 없다. 새 프레임워크 도입은 사용자 승인 사항이다. 대신 재지 않은 문장은 넣지 않는다는 기준을 판단 기준에 넣었다 |
| 주석은 이유만 한 줄로 | 주석 정책은 프로젝트가 정한다. v4.26.0에서 주석 금지 규칙을 넣지 않은 것과 같은 이유다 |

## 근거 숫자

| 확인 | 결과 |
|------|------|
| `tests/subagent-start.bats` red | 9건 중 8건 실패. 훅, 규칙 파일, 등록이 없을 때 |
| 같은 테스트 green | 9건 통과 |
| stdin을 읽는 변형 훅 | 10초 제한에 걸림. 원본은 즉시 종료. stdin 테스트가 읽기 대기를 잡는다 |
| 팀 모드 게이트에 `NOT_CHECKED` 넣기 | `NOT_CHECKED`와 `FINDING_COUNT: 0`은 통과. `NO_FINDINGS`와 `NOT_CHECKED`만 있으면 거부 |

SubagentStart 주입이 서브에이전트에 보이는지는 카나리아 실행으로 확인했다.
최소 플러그인에 훅 스크립트, 래퍼, 등록 문자열을 그대로 복사했다. 규칙 파일 끝에는 실행마다 새로 만든 무작위 문자열을 붙였다.
중첩 `claude -p` 세션에 이 플러그인만 붙이고 서브에이전트에게 그 문자열을 되말하게 했다.
부모 프롬프트에는 문자열이 없고, 파일 읽기 도구는 막았다.
