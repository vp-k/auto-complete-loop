# 보고 작성 규칙 (단일 출처)

작업 보고, 리뷰 결과, 설명, handoff 요약, 커밋 메시지 본문에 적용한다.
이 파일은 `hooks/session-start.sh`가 매 세션 시작 시 컨텍스트로 주입한다.
규칙을 바꿀 때는 이 파일만 고친다.

## 양식 (순서 고정)

1. **결론** - 첫 줄 한 문장. 됐는지 안 됐는지, 검증했는지부터 쓴다.
2. **변경 표** - 무엇을 어디에 바꿨는지. 열은 대상 / 변경 / 근거. 칸은 한 줄.
3. **근거 숫자 표** - 테스트 수, 커밋 해시, 건수는 본문이 아니라 표에 넣는다.
4. **남은 것** - 하지 않은 것, 사용자가 결정할 것, 다음 명령. 없으면 "없음"이라고 쓴다.

## 하드 규칙

1. 한 문장에 뜻 하나. 문장은 40자 안팎으로 쓰고 60자를 넘기지 않는다. 조건절은 문장을 나눈다.
2. 용어, 약어, 플래그 이름은 처음 나올 때 한 줄로 풀어 쓴다. 두 번째부터는 이름만 쓴다.
3. 본문에 `파일:줄번호`, 함수명, 옵션명을 나열하지 않는다. 필요하면 표나 코드 블록으로 뺀다.
4. 본문 한 문단에 숫자를 두 개 이상 넣지 않는다. 숫자는 표로 옮긴다.
5. 괄호 안에 문장을 넣지 않는다. 대시(—), 화살표(→), 가운뎃점(·)으로 절을 잇지 않는다.
6. 목록 항목 하나는 두 문장 이내. 세 문장이 필요하면 항목을 나눈다.
7. 500자 안쪽 보고에는 헤더를 쓰지 않는다.

## 금지 사례

- 나쁜 예: "A를 B로 바꿔(C 때문에, D는 유지) E가 F되던 문제를 해소하고 G도 정리." 좋은 예: 네 문장으로 나눈다.
- 나쁜 예: "`state.sh:442`의 `_rr_commit_rounds`가 `--round-kind` 없이 호출되어". 좋은 예: "라운드 계수 함수가 종류 인자 없이 호출됩니다." 이름과 위치는 표로 뺀다.
